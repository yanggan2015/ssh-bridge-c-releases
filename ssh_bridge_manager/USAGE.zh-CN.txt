1. 程序是做什么的
--------------------------------------------------------------------------------

终端共享管理工具在本机提供两类“桥接”通道，并共用一个 Web 管理页与 HTTP API：

  A) 串口桥（boards）
     - 连接本机串口（如 COM3）
     - 对外提供入站 SSH（例如本机 2201 端口）
     - 可通过浏览器 / HTTP 发送命令、查看日志

  B) SSH Link（ssh）
     - 主动连接远端 SSH（例如开发板 / 服务器）
     - 同时在本机再开一个入站 SSH 端口，方便转发会话
     - 同样可通过浏览器 / HTTP 操作

典型用途：实验室/产线多板管理、远程串口、把远端 shell 统一接到本机端口与网页。

2. 解压后目录里有什么
--------------------------------------------------------------------------------

  ssh_bridge_desktop.exe     桌面窗口（推荐，内嵌网页）
  ssh_bridge_manager.exe     后端 / 命令行主程序（须与同目录 DLL 一起保留）
  *.dll                      运行时依赖（勿删、勿挪走）
  run.bat                    一键启动桌面窗口（推荐）
  config.json.example        配置模板
  ui_settings.json.example   界面主题等可选模板
  README.txt                 快速入门
  使用说明.txt               本文档（详细说明）
  VERSION.txt                本构建的版本号、编译时间、过期时间

首次可无手动配置：无 config.json 时会自动创建空配置。也可复制 example。运行后还可能在配置目录下生成：

  logs/                      通道日志（若开启 log_enabled）
  keys/                      SSH 主机密钥等运行时文件
  ui_settings.json           Web 界面设置

3. 快速开始（最短路径）
--------------------------------------------------------------------------------

  1) 解压 zip 到任意目录（路径中尽量避免特殊权限问题；建议英文路径）
  2) 配置：
       - 首次运行会在工具目录自动生成空 config.json，也可：
           copy config.json.example config.json
       - 按实际修改 default / boards / ssh（也可启动后在网页里添加通道）
  3) 双击 run.bat 或 ssh_bridge_desktop.exe（内嵌窗口，无需浏览器）
  4) 若只用命令行后端 ssh_bridge_manager.exe，再在浏览器打开：
       http://127.0.0.1:18081/
     页面内还有：
       /config   配置说明页
       /help     根据当前配置生成的操作帮助

命令行等价启动：

  ssh_bridge_desktop.exe          # 桌面窗口（推荐）
  ssh_bridge_desktop.exe --smoke-test
  ssh_bridge_manager.exe
  ssh_bridge_manager.exe help
  ssh_bridge_manager.exe version

桌面壳说明：
  - 自动启动同目录 ssh_bridge_manager.exe 并嵌入网页
  - 需要 Microsoft Edge WebView2 Runtime（Win11 通常自带）
  - 下载：https://developer.microsoft.com/microsoft-edge/webview2/

4. 配置文件查找规则
--------------------------------------------------------------------------------

未指定 -c 时，按顺序查找：

  1) 当前工作目录下的 .\config.json
  2) 工具（exe）目录下的 config.json
  3) 用户目录：%USERPROFILE%\.ssh-bridge\config.json

都找不到时，在工具目录自动创建一份空配置（可直接网页加通道）。

指定配置：

  ssh_bridge_manager.exe -c D:\path\config.json

查看将使用哪份配置：

  ssh_bridge_manager.exe which-config
  ssh_bridge_manager.exe which-config -c D:\path\config.json

说明：
  - 运行时数据（logs、keys、ui_settings.json）写在“实际使用的那份
    config.json 所在目录”。
  - 若用 run.bat 启动，当前目录就是解压目录，优先用旁边的 config.json。
  - 也可把 config 放到用户目录，多处拷贝 exe 时共享同一份配置。

覆盖 HTTP 端口（不改配置文件）：

  ssh_bridge_manager.exe --http-port 18081

--------------------------------------------------------------------------------
5. config.json 字段说明
--------------------------------------------------------------------------------

顶层结构：

  {
    "default": { ... },   // 全局默认（入站账号、HTTP、日志等）
    "boards":  { ... },   // 串口桥通道（可多个）
    "ssh":     { ... }    // SSH Link 通道（可多个）
  }

5.1 default

  username / password
      本机入站 SSH 的登录名与密码（串口桥与 SSH Link 的入站侧共用这套默认账号，
      除非实现上另有覆盖）。password 为空字符串或省略该字段时表示不需要入站密码。

  buffer_size
      内存日志环缓大小（字节），默认示例 1048576（1MiB）。

  log_enabled
      true/false，是否写磁盘日志到 log_dir。

  log_dir
      日志目录，相对路径相对于 config.json 所在目录，例如 "./logs"。

  http_port
      Web / HTTP API 监听端口，默认 18081。

5.2 boards（串口桥）— 每个 key 是通道名

  示例通道名：board-win

  enable          是否启用该通道
  port            本机入站 SSH 端口（如 2201）
  serial_device   Windows 一般为 "COM3"；若 COM 号较大可用 "COM10" 等
  baudrate        波特率，如 115200、1500000
  timestamp       true 时日志可带时间戳（按实现）

  入站 SSH 连接示例（在另一台机器或本机）：

    ssh -p 2201 root@127.0.0.1

  （用户名/密码为 default.username / default.password）

5.3 ssh（SSH Link）— 每个 key 是通道名

  示例通道名：yocto-build

  enable            是否启用
  port              本机入站 SSH 端口（如 2301）
  target_host       远端主机 IP 或域名
  target_port       远端 SSH 端口，通常 22
  target_username   远端登录名
  target_password   远端密码
  timestamp         可选

  行为概要：
    - 程序连接到 target_host:target_port
    - 同时在本机 port 上接受入站 SSH，会话转发到远端 shell
    - Web/HTTP 可用 link=通道名 发送命令、读日志

  入站示例：

    ssh -p 2301 root@127.0.0.1

5.4 安全提示

  - 不要把含真实密码的 config.json 发给他人或提交到公开位置。
  - 发行包里的 config.json.example 仅含占位密码。
  - 入站 SSH 与 HTTP 默认监听本机可达地址；若在不可信网络暴露，请自行做好
    防火墙与强密码策略。

7. Web 管理界面
--------------------------------------------------------------------------------

默认地址（http_port=18081 时）：

  总览 / 终端面板：  http://127.0.0.1:18081/
  配置相关页面：    http://127.0.0.1:18081/config
  动态帮助：        http://127.0.0.1:18081/help
  状态 JSON：       http://127.0.0.1:18081/status
  操作列表 JSON：   http://127.0.0.1:18081/operations

在 Dashboard 上通常可以：

  - 查看各通道连接状态
  - 打开终端视图，与串口或 SSH Link 交互
  - 发送命令、查看滚动日志
  - 切换主题等（写入 ui_settings.json）

若页面打不开：
  - 确认进程已启动且无报错退出
  - 确认 http_port 未被占用
  - 尝试 http://127.0.0.1:<你的端口>/
  - 检查防火墙是否拦截

8. HTTP API（脚本 / 自动化）
--------------------------------------------------------------------------------

以下以 http://127.0.0.1:18081 为例。串口通道用 board=名称，SSH Link 用 link=名称。

8.1 状态

  curl http://127.0.0.1:18081/status
  curl "http://127.0.0.1:18081/status?board=board-win"
  curl "http://127.0.0.1:18081/status?link=yocto-build"

8.2 读日志

  curl "http://127.0.0.1:18081/log?board=board-win&chars=4096"
  curl "http://127.0.0.1:18081/log?board=board-win&lines=100"
  curl "http://127.0.0.1:18081/log?link=yocto-build&chars=4096"

8.3 异步发命令（立即返回，输出需再读 /log）

  curl -H "Content-Type: application/json" ^
    -d "{\"board\":\"board-win\",\"command\":\"uname -a\"}" ^
    http://127.0.0.1:18081/command

  curl -H "Content-Type: application/json" ^
    -d "{\"link\":\"yocto-build\",\"command\":\"uname -a\"}" ^
    http://127.0.0.1:18081/command

8.4 阻塞发命令（等待 timeout 秒后返回输出，默认约 2 秒）

  curl -H "Content-Type: application/json" ^
    -d "{\"board\":\"board-win\",\"command\":\"uname -a\",\"timeout\":3}" ^
    http://127.0.0.1:18081/command_block

8.5 清日志 / 重连

  curl -H "Content-Type: application/json" ^
    -d "{\"board\":\"board-win\"}" ^
    http://127.0.0.1:18081/log/clear

  curl -H "Content-Type: application/json" ^
    -d "{\"link\":\"yocto-build\"}" ^
    http://127.0.0.1:18081/reconnect

8.6 其它

  GET/POST /ui_settings     读写界面设置
  POST /send_keys           按键序列（见 /operations 与 /help）
  GET  /operations          机器可读的操作清单
  GET  /help                人类可读、按当前配置生成的帮助

完整、与当前运行配置绑定的示例，请优先打开浏览器 /help。

9. 用 SSH 客户端连接入站端口
--------------------------------------------------------------------------------

1) 在 config.json 中确认通道 enable=true，并记住 port。
2) 启动本程序。
3) 使用任意 SSH 客户端：

     ssh -p <port> <default.username>@<本机IP或127.0.0.1>

4) 串口桥：交互内容进出串口。
   SSH Link：交互内容转发到 target 远端 shell。

同一通道也可同时被 Web / HTTP 使用；请注意多客户端同时写入时的交叉输出。

10. 版本有效期（180 天 / 约半年）
--------------------------------------------------------------------------------

每个构建写入编译时间戳；自编译时刻起约 180 天（半年）内 API 保持使能。
过期后：

  - 进程仍可启动，网页会提示下载最新版本或联系 yanggan2015@foxmail.com
  - HTTP / WebSocket API 返回禁用（api_enabled=false）
  - 仍可执行：help / version / which-config

查看本机包信息：

  ssh_bridge_manager.exe version
  type VERSION.txt

下载：

11. 常见问题
--------------------------------------------------------------------------------

Q: 双击 exe “没反应”或立刻退出？
A: 常见原因：
   - 缺少同目录 DLL（请保持解压目录完整，不要只拷贝 exe）
   - 找不到 config.json（先 copy example，或放到用户目录）
   - 版本已过期（运行 version 查看，下载新 Release）
   建议用 run.bat 启动，便于看到错误提示。

Q: 串口打不开？
A: 确认设备管理器中的 COM 口号与 serial_device 一致；端口未被其它程序占用；
   波特率与设备一致；有权限访问串口。

Q: SSH Link 连不上远端？
A: 检查 target_host/port、账号密码、网络与防火墙；在 status 或日志中看连接状态；
   可对应该通道调用 /reconnect。

Q: 网页能开但板卡列表为空？
A: 确认至少有一个 enable=true 的通道；看 /status 返回；确认浏览器访问的是本进程
   的 http_port。

Q: 可以只发可执行文件给同事吗？
A: 可以发整个解压目录（exe+DLL+本文档+example）。不要附带你的真实 config.json。

Q: 源码在哪里？
A: 本产品源码闭源，公开发布仓仅提供可执行包，不含工程源码。

12. 文件与依赖注意
--------------------------------------------------------------------------------

  - 必须把 ssh_bridge_manager.exe 与同目录全部 *.dll 放在一起。
  - 不要从其它机器零散拷贝单个 DLL 覆盖，以免版本不匹配。
  - 杀毒软件若拦截，请将解压目录加入信任区后重试。
  - 升级：下载新 zip，解压到新目录；可复用旧 config.json（建议先备份）。
